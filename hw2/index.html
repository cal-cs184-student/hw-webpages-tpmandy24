Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

De Casteljau’s algorithm evaluates a Bezier curve using repeated linear interpolation between control points. Given a parameter t between 0 and 1, we compute new points between every pair of adjacent control points using linear interpolation. The formula we use is: newPoint = (1 - t) * p1 + t * p2 Each subdivision step reduces the number of control points by one. We continue applying this process until only one point remains. That final point lies on the Bezier curve at parameter t. This algorithm is numerically stable and avoids directly computing polynomial equations. We implemented the recursive subdivision step inside BezierCurve::evaluateStep. The function takes a vector of 2D control points and produces a new vector where each element is the linear interpolation of adjacent points using the member variable t. Each call performs one level of subdivision. When this function is repeatedly called, the control polygon collapses to a single point, which is the evaluated point on the curve.

Part 2: Bezier surfaces with separable 1D de Casteljau

Bezier surfaces extend the 1D de Casteljau algorithm by applying it twice. Since a Bezier surface is defined by an n by n grid of control points, we evaluate it in two stages. First, each row of control points is treated as a Bezier curve parameterized by u. Using the same 1D de Casteljau algorithm from Part 1, we evaluate each row at parameter u. This produces one intermediate point per row. Next, we treat those intermediate points as a new Bezier curve parameterized by v. We apply the same 1D algorithm again to evaluate this curve at parameter v. The result is a single point that lies on the Bezier surface at parameters u and v. This works because Bezier surfaces are separable, meaning we can evaluate one parameter at a time. Weimplemented three functions. BezierPatch::evaluateStep performs one interpolation step on a vector of 3D points using the same linear interpolation formula as in Part 1. BezierPatch::evaluate1D repeatedly calls evaluateStep until only one point remains, fully evaluating a Bezier curve at a given parameter. BezierPatch::evaluate first evaluates each row of control points at parameter u, stores the resulting intermediate points, and then evaluates those points at parameter v to compute the final surface point.

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

To compute area-weighted vertex normals, we iterated through all faces incident to a vertex using the half-edge structure. Starting from the vertex’s outgoing halfedge, we traversed neighboring triangles by repeatedly following the twin and next pointers. For each triangle, we computed two edge vectors using the positions of its vertices and took their cross product to obtain the face normal. Since the magnitude of the cross product is proportional to the triangle’s area, this automatically produces an area-weighted normal. We accumulated these face normals and normalized the final result to obtain a unit vertex normal. This implementation allows smooth shading across the surface when Phong shading is enabled. In flat shading, each triangle appears visibly distinct because each face uses its own normal. After toggling to vertex normals, the shading becomes smooth and continuous across the surface, confirming that the area-weighted normals were implemented correctly.

Part 4: Edge flip

To implement the edge flip operation, we first retrieved all halfedges, vertices, edges, and faces associated with the selected edge and its two adjacent triangles. Since edge flipping does not create or delete elements, we only reassigned pointers. We carefully updated the next, twin, vertex, edge, and face pointers for all six halfedges involved in the local configuration. We also reassigned the halfedge pointers for the affected vertices and faces to ensure that every element in the mesh continued to reference valid neighbors. We added a boundary check at the start of the function to prevent flipping boundary edges. The operation runs in constant time because it only modifies a fixed number of local elements. During debugging, we drew a diagram of the two triangles involved in the flip and labeled all halfedges, vertices, and faces before and after the operation. Most issues were caused by forgetting to update one of the halfedge pointers or assigning an incorrect next pointer, which led to broken mesh connectivity. To debug, we repeatedly flipped the same edge multiple times and flipped nearby edges to ensure the mesh remained consistent. Ensuring that every pointer was explicitly reassigned resolved the issues.

Part 5: Edge split

To implement the edge split operation, we first retrieved all halfedges, vertices, edges, and faces associated with the selected edge and its two adjacent triangles. Since splitting an edge modifies the local mesh structure, we carefully stored references to all elements before making any changes. We ignored boundary edges by returning immediately if the selected edge was on the boundary. For interior edges, we created a new vertex at the midpoint of the original edge and assigned its position as the average of the two endpoint vertex positions. Next, we created the necessary new halfedges, edges, and faces to subdivide the two original triangles into four smaller triangles. We then reassigned all next, twin, vertex, edge, and face pointers for both existing and newly created elements. Because the half-edge data structure is pointer-based, it was important to explicitly update every pointer in the local neighborhood to maintain mesh consistency. The implementation performs a constant amount of work since it only modifies a fixed number of elements around the selected edge.

Part 6: Loop subdivision for mesh upsampling

We implemented Loop subdivision in three phases. First, before any topology changes, we computed new positions for all existing vertices using the weighted average formula (1 - n*u) * original_position + u * neighbor_sum, where u = 3/16 for degree-3 vertices and u = 3/(8n) otherwise. We also precomputed new positions for edge midpoints using the formula 3/8 * (A + B) + 1/8 * (C + D), where A and B are the edge endpoints and C and D are the opposite vertices from adjacent faces. Precomputing all geometry before modifying the mesh ensured we did not mix old and new values during subdivision. Second, we performed the topological 4-1 subdivision. We first snapshotted all original edges to avoid splitting edges created during the same pass. Each original interior edge was split exactly once, and the precomputed midpoint position was assigned to each new vertex. New diagonal edges created by the split were marked as isNew = true, while edges lying along the original edge were marked as isNew = false. After splitting, we flipped only those new edges that connected one old vertex and one new vertex, which completed the proper 4-1 subdivision structure. A key debugging insight was printing the isNew flags for vertices and edges during the flipping step. This helped us verify which edges were actually being flipped. We observed that edge halfedge orientation consistently made one endpoint the new midpoint vertex, which clarified how to correctly identify edges that required flipping. After Loop subdivision, sharp corners and edges progressively become smoother. The weighted averaging pulls vertices toward their neighbors, reducing curvature and rounding high-curvature regions. After three or four iterations, even very sharp creases become nearly invisible. Pre-splitting edges along sharp features before subdivision helps preserve them. Increasing local vertex density reduces how strongly averaging alters the shape, allowing sharp features to remain more prominent after subdivision. The cube becomes asymmetric under repeated subdivision because each square face is triangulated by a single diagonal, and these diagonals are not arranged symmetrically across all faces. Since Loop subdivision averages vertex positions based on local connectivity, vertices with different triangulation neighborhoods shift differently, introducing asymmetry. Pre-processing the cube by splitting each face diagonal to create an X-shaped triangulation with a central vertex gives each corner vertex a more symmetric neighborhood. After this adjustment, repeated subdivision produces a much more symmetric rounded cube.
